# Native analytics dispatch contract

IPC command: `analytics_dispatch({input})`; backend `analytics::dispatch(&AppConfig, Value)` returns JSON or a sanitized string error. `analytics::sync_due(&AppConfig)` is safe for startup/resume/6h timers: it only processes configured due connections after schema exists. Credentials never cross IPC.

All fields camelCase. Actions:

- `{action:"status"}` => `{schemaReady:boolean,migrationRequired:boolean,paused:boolean,jobs:Job[],capabilities:Capability[],limits:{maxBytes,maxRows,maxColumns}}`. Schema is **not** auto-applied. `{action:"applySchema"}` explicitly applies additive migration 010 to the configured local app database.
- `{action:"query",platform?,accountId?,connectionId?,sourceKind?:"api"|"import",sourceId?,metric?,from?:"YYYY-MM-DD",to?:"YYYY-MM-DD",limit?:number,offset?:number}` => `{observations:Observation[],hasMore:boolean,coverage:Job[],totalIsNotComputed:true}`. Limit max 1000. Date filters select overlapping periods; no totals or interpolated history.
- `{action:"sources",platform?,accountId?,sourceKind?}` => `{sources:Source[]}`.
- `{action:"sync",connectionId?}` => `{jobs:Job[],paused:boolean}`. Without a connection processes all due jobs. Explicit connection requests one manual refresh (unless globally paused). Jobs are discovered only from verified OAuth connections, never inferred from channel names.
- `{action:"pause",paused:boolean}` => status response. Pause survives restart.
- `{action:"importPreview",filename:"report.csv"|"report.tsv"|"report.xlsx",text?:string,bytesBase64?:string,platform:"youtube"|"instagram"|"facebook"|"threads"|"tiktok"|"naver_blog"|"naver_clip"|"x",accountId:string,label?:string,timezone:"Asia/Seoul",aggregation:"period"|"cumulative"|"snapshot",periodStart?:"YYYY-MM-DD",periodEnd?:"YYYY-MM-DD",mapping?:Mapping,definitions?:{[metric]:{definition:string,unit:string}}}` => `{previewId:string,headers:string[],sample:string[][],rowCount:number,observationCount:number,observations:Observation[],errors:string[],warnings:string[],canCommit:boolean,expiresAt:string}`. Send **either** text or bytesBase64, never paths. CSV/TSV/table pasted as text; XLSX as base64. First call may omit mapping to inspect headers; call again with original bytes/text plus mapping.
- `Mapping = {date?:columnName,endDate?:columnName,contentId?:columnName,metric?:columnName,value?:columnName,metrics?:{[columnName]:metricName},dimensions?:{[dimensionName]:columnName}}`. Supply either long form `metric+value` or wide `metrics`. A date column gives each row its actual period; otherwise explicit periodStart/periodEnd are mandatory. Empty values become `not_returned` + null, zero remains available zero. Definitions preserve platform report wording; missing definitions are labelled as user-mapped report columns, never API-equivalent.
- `{action:"importCommit",previewId:string,replaceImportId?:string}` => `{source:Source,idempotent:boolean,replacedSourceId:string|null}`. Same normalized data + metadata is idempotent only for an active import; row order and provenance row numbers do not change the digest. Removed/replaced data can be re-imported, and source metadata records reactivation revisions. Overlapping different imports require explicit `replaceImportId`; only import data of the same platform/account/timezone can be replaced. API observations cannot be overwritten. Preview expires in 24h.
- `{action:"importHistory",platform?,accountId?}` => `{imports:Source[]}` (includes removed/replaced audit entries).
- `{action:"importRemove",sourceId:string}` => `{removed:boolean,sourceId:string}`. Only imported observations are deleted; audit metadata remains. Idempotent.

`Observation = {id?:string,sourceId?:string,platform:string,accountId:string,connectionId?:string|null,sourceKind:"api"|"import",metric:string,definition:string,unit:string,aggregation:"period"|"cumulative"|"snapshot",periodStart:string,periodEnd:string,timezone:string,contentId:string,dimensions:object,value:number|null,status:"available"|"not_returned"|"unavailable",observedAt:string,apiVersion:string,provenance:object,authorizationExpiresAt?:string|null,verificationExpiresAt?:string|null,expiresAt?:string|null}`.

`Source = {id,sourceKind,platform,accountId,connectionId,label,filename,digest,status:"active"|"replaced"|"removed",metadata,createdAt,removedAt,authorizationVerifiedAt,authorizationExpiresAt}`.

`Job = {connectionId,platform,accountId,status:"pending"|"running"|"ready"|"partial"|"permission_required"|"reconnect_required"|"rate_limited"|"error"|"awaiting_report",lastSyncAt,nextSyncAt,cursor:object,coverage:object,message:string}`. Coverage contains actual returned period/snapshot information and partial collection boundaries; empty responses do not manufacture zero days. `cursor` contains only provider IDs/page markers, never access tokens or signed download URLs.

`Capability = {platform,apiVersion,accountRequirement,requiredScopes:string[],metrics:string[],history:string,latency:string,limitations:string[],manualOnly:boolean}`. X/Naver Blog/Naver Clip manualOnly true. No composite performance score or revenue/advertising metrics.

## Fixed native report queries

`{action:"reportQuery",connectionId,platform,accountId,report,range:"7d"|"28d"|"90d"|"custom",from?,to?,contentId?,breakdown?:"age"|"gender"|"country"|"city",audienceMetric?:"follower_demographics"|"engaged_audience_demographics",timeframe?:"this_week"|"last_14_days"|"last_30_days"|"last_90_days"}` => `{sourceId,observations:Observation[],coverage,status,message,nextCursor}`. An optional `cursor:{startIndex:number}` continues bounded YouTube reports (maximum 10,000). The result is persisted in the API source, with original dimension values; selecting a date filter never prorates a period total. `custom` requires ISO from/to. One request is at most 366 days; Instagram at most 90 days. Instagram audience uses an explicit provider `timeframe`, default `last_30_days`; the ordinary 7/28/90-day filter is never converted to an audience timeframe. Labels are 이번 주(월요일부터), 최근 14일, 최근 30일, 최근 90일. `this_week` is a calendar week starting Monday, not rolling seven days. Demographic results remain collection-time snapshots with providerTimeframe/calendarStartRule in provenance and coverage; exactBoundsReturned is false because the API does not return exact boundary timestamps. No custom date history is claimed.

No raw metric names, URLs or provider filter expressions are accepted in this action. Video/Reel queries verify the returned owner against the pinned account before requesting insight fields. A provider error for one metric/report yields an unavailable observation and keeps other report results. Empty demographic/retention responses are `not_returned`, with `availability` identifying that privacy threshold, latency and genuine absence cannot be distinguished unless the provider specifies the cause.

Default background sync requests a 90-day available history window. YouTube also persists traffic/country/device/demographic reports. Snapshot-only platforms still store only collection-time observations. A bounded page/request cap records partial coverage and a cursor; no all-history completeness is implied.

`{action:"deleteApiCache",connectionId,accountId?}` => `{deletedSources:number}` deletes only API observations/jobs for that exact connection, never imports or user-authored content. In-flight jobs are fenced by a lease token so a deleted job cannot recreate its cache after deletion. Pause is persisted and checked before each new HTTP request.

## YouTube data lifecycle

SQL010 adds typed `authorization_verified_at` / `authorization_expires_at` to API sources and `verification_expires_at` to observations. Live `channels.list(mine=true)` reconfirms the pinned owner. Returned video IDs are checked with `videos.list` in batches of at most 50, including channel ownership; confirmed deleted/unowned IDs remove their prior API observations. Historical Analytics/Reporting periods may remain when recently verified, but no authorization or video-existence verification is treated as permanent.

The conservative deadline is 30 days after positive verification. Every dispatch and launch/resume/due-sync performs offline expiry cleanup **before** pause handling; query SQL independently excludes expired/unverified YouTube API facts. Expired sources and related job cursors are removed, so offline resume cannot redisplay expired facts. Per-video deadlines also remove stale videos while a channel source remains current. Confirmed authentication invalidation and scoped access failures remove that exact account's API cache. `analytics::purge_youtube_connection(config,connectionId)` is the disconnect/revocation hook. All these paths preserve manual imports and other connections. Legacy API records without verification deadlines expire conservatively.

A 429 halts further wire requests for that account transport. The greatest Retry-After delay and rate_limited status propagate through nested reports into persisted nextSyncAt; manual requests cannot bypass the wait.

XLSX preflight follows/validates all workbook relationship targets that Calamine can resolve to its worksheets directory, independent of declared relationship Type. Nonstandard/non-XML targets are rejected before Calamine opens worksheets. Explicit and implicit row/column coordinates are bounded before range allocation.

[YouTube stored-data authorization and deletion policy](https://developers.google.com/youtube/terms/developer-policies#e.-handling-youtube-data-and-content) informs the 30-day lifecycle. This implementation uses conservative cache deletion when revalidation is unavailable.

Loaded-row expiry guard: native query and reportQuery serialize `authorizationExpiresAt`, `verificationExpiresAt`, and effective `expiresAt` (ISO timestamp or null). For API YouTube, effective expiry is the minimum applicable authorization/video deadline. The frontend must remove a loaded API YouTube row once its expiry passes, and reload/treat legacy API YouTube rows without a deadline as unavailable. Imports and other platforms have null deadlines. Original periodStart/periodEnd remain unchanged; range selection uses overlap and never clips or prorates reported values.

## Durable local report ownership

Migration011 adds `analytics_report_owners(platform,account_id,channel_id,first_seen_at)`. A verified `bindChannel` records the local channel UUID, prior remote account and new remote account in the same transaction as the binding. Existing bindings are backfilled when the explicit migration runs. First owner is retained for each platform/account identity, including a tombstone UUID after local channel deletion: reusing a remote account on a different local channel cannot transfer that channel's old reports. Original source `accountId`, numbers, periods, definitions and row provenance remain unchanged. New reports use the stable local channel UUID as accountId.

`query`, `sources` and `importHistory` accept optional `channelId` (local UUID). Imported rows resolve through that channel's persistent owners; API rows resolve only through its current exact connection/platform/account binding. Other ordinary filters still intersect this scope. Source/history and observation results add `reportChannelId:string|null`. The frontend uses this native association for historical remote imports; an unassociated remote import is hidden rather than guessed from a reused OAuth binding. Local UUID imports remain accessible before the first OAuth binding. Job coverage returned by a channel-scoped query is restricted to its current exact binding. Removing/disconnecting an OAuth grant leaves manual report aliases intact.

For correction, choose the active original source **before** mapping preview. Send `importPreview` with `{channelId,platform,accountId:originalSource.accountId,replaceImportId:originalSource.id,...fileAndMapping}`. A new report sends `{channelId,platform,accountId:channelId,...fileAndMapping}`. The preview stores the owner and optional replacement immutably; `importCommit` sends its `previewId` and the same captured `replaceImportId`. Changing the replacement invalidates the frontend form/review; native commit rejects an altered or omitted replacement. The native preview also rejects owners outside the selected channel. `importRemove` accepts `{sourceId,channelId}` and checks that source's original owner belongs to that channel. Correction overlap checks include every retained owner for the selected local channel; an explicit matching original source is required. Existing non-channel callers retain the original exact-account contract.

Both migrations010 and011 grant only SELECT/INSERT/UPDATE/DELETE on their analytics tables to `toris_app`; schema creation remains owner-only. Migration011 repeats the grants to repair early feature installations that had already recorded migration010. No app-role DDL or startup migration is performed.
