## 원인과 수정

0.3.0에서 기존 설정 화면을 복원하면 제거된 `opencodexAllowedModels` 배열의 `.join()`을 호출했습니다. 실제 Rust 공개 설정 응답에는 이 필드가 없었고, React 루트가 실패해 창의 본문이 비었습니다. 이전 브라우저 fixture는 삭제된 필드를 계속 제공해 문제를 가렸습니다.

설정 폼·타입·저장에서 사용하지 않는 코딩·모델 실행기 필드를 제거하고 fixture를 실제 공개 응답에 맞췄습니다. 비밀값을 비워 저장할 때 기존 DB·수집 키를 유지하는 동작은 보존합니다. 시작 오류 경계는 사용자 데이터 삭제 없이 한국어 복구 안내와 키보드로 실행할 수 있는 다시 불러오기 버튼을 표시합니다.

## 실제 설치 앱 확인과 후속 오류

사용자가 Mac에서 키체인 승인을 완료한 뒤 실제 `/Applications/Toris Studio.app`의 본문과 설정 화면이 열리는 것을 접근성 상태와 화면 캡처로 확인했습니다. 설정에서 `0.3.1` 버전과 로컬 DB 연결을 확인했고, 정상 종료·재실행 후에도 설정 본문이 복원됐습니다. 기존 채널 1개·콘텐츠 1개와 저장된 트렌드 목록의 실제 DB 조회도 통과했습니다. 비밀값을 노출하거나 계정·데이터를 다시 입력하지 않았습니다.

이후 SNS 연결 조회에서 별도 오류를 확인했습니다. 새 OAuth 연결 저장소가 사용하는 메타데이터·연결·복구 키들이 macOS 자격 증명 저장소의 허용 목록에 빠져 있었습니다. OS 접근 이전의 검증 오류가 일반 권한 보류 메시지로 반환되어, 실제 권한 문제가 없는데도 SNS에 경고가 표시됐습니다. 설정의 권한 재시도 버튼이 나타나지 않는 원인도 이 차이입니다. 이 오류는 [0.3.2](./0.3.2.md)에서 수정했고, 실제 설치 앱에서 콘텐츠·트렌드 조회 후 SNS로 돌아와 주기 재조회를 거쳐도 경고가 재발하지 않는 것을 확인했습니다. [0.3.2 검증 기록](./0.3.2-verification.md)에 후속 결과를 구분해 기록합니다.

## 서명과 범위

Mac은 ad-hoc 코드 서명이며 Apple 공증이 적용되지 않았습니다. Windows Authenticode는 미설정입니다. Tauri 업데이트 서명은 기존 공개 키를 유지합니다. 실제 SNS 제공자 로그인·성과 조회와 UI fixture 검사는 구분하며, 제공자 계정의 실제 조회 완료를 주장하지 않습니다. 원래 작업 디렉터리의 미추적 폴더와 사용자 데이터는 배포에 포함하지 않습니다.
