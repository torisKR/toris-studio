## 실제 앱에서 확인한 원인

0.3.1 설치 앱에서 키체인 승인 후 SNS·콘텐츠·설정 본문, 정상 종료·재시작 시 설정 복원, 기존 채널 1개·콘텐츠 1개와 트렌드 목록의 실제 DB 조회를 확인했습니다. 이후 SNS 연결 목록 조회에서 권한 경고가 재발했습니다.

새 OAuth 연결 저장소가 사용하는 두 인덱스, UUID가 포함된 다섯 연결·복구 키 형식과 세 가지 레거시 보존 키 형식이 macOS `Vault` 허용 목록에 없었습니다. 검증 실패는 OS 접근 이전에 발생하므로 키체인 차단 상태가 설정되지 않았고, SNS에는 일반 권한 보류 오류가 표시되지만 설정에는 권한 재시도 버튼이 나타나지 않았습니다. 사용자 재승인으로 해결할 수 있는 오류가 아니었습니다.

새 키 형식과 실제 생성 규칙에 맞는 UUID·제공자·길이만 허용했습니다. 기존 설정 슬롯·서비스·6개 제공자는 유지하며 임의의 저장소 키는 거부합니다. 24개였던 항목 개수 한도는 기존 데이터와 새 연결·복구 기록을 함께 보관하도록 2,048개로 조정했습니다. 스키마 2, 항목당 65,536바이트와 전체 인코딩 1,500,000바이트 제한은 유지합니다. 기존 항목이나 삭제 표시는 지우지 않습니다. Windows는 기존 네이티브 저장 어댑터를 유지합니다.

## 로컬 검사와 리뷰

- 수정 전 실제 OAuth 생성 코드와 실제 `Vault` 검증기를 연결한 검사에서 동일한 권한 보류 오류로 실패하는 것을 확인했습니다. OS 백엔드만 메모리로 대체했으며 사용자 키체인·계정·DB에 접근하지 않았습니다.
- 수정 후 실제 연결 저장·인덱스 커밋 중단 복구·조회·레거시 복사·클라이언트 변경 백업·연결 해제·재시작과 다른 연결 보존을 검사했습니다. 잘못된 키·UUID·제공자·길이는 OS 접근 없이 거부되고, 실제 승인 거절은 명시적 재시도 전까지 캐시됩니다.
- 기존 24개 항목과 새 연결 기록의 동시 보존, 2,048개 항목·개별 바이트·전체 바이트 상한을 검사했습니다. Windows 청크 저장 회귀 검사도 통과했습니다.
- Rust 전체 356개 통과·20개 명시적 무시, 실패 없음. JavaScript 196개 중 195개 통과·1개 명시적 건너뜀, 실패 없음.
- 루트·데스크톱 TypeScript와 프로덕션 Vite 빌드, 브라우저·패키지·게시 계약 41개, OAuth 콜백 13개 통과. 잠금 파일 기준 의존성 취약점 0건.
- 독립 리뷰에서 중대한 문제 없음. Rust 형식·변경 검사·스테이징 비밀값 검사를 통과했습니다.
