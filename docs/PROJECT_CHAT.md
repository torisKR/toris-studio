# 프로젝트 채팅 (Orca식 앱 폴더 + 에이전트 채팅)

[Orca](https://github.com/stablyai/orca)처럼 앱 폴더를 프로젝트로 넣고, 그 폴더에서 Claude Code·Codex와 **채팅으로** 기획하고 구현한다. 주 메뉴 맨 위 **프로젝트**에서 연다.

```
┌ 프로젝트 ───────┬ 대화 ─────────────────────────────┬ 변경 사항 ────────┐
│ pocket-app      │ 로그인 화면을 만들어줘    [기획|편집] │ ?? src/Login.tsx  │
│  ├ 새 대화      │  > Write src/Login.tsx  (펼치면 결과) │  M README.md      │
│  └ 로그인 …     │  > Bash pnpm test       (실패 표시)   │ diff (+/- 색 구분) │
│ other-app       │  완료 · 22초 · $0.65                 │                   │
│                 │ [메시지 ………………] [받는 에이전트 ▾] 보내기 │                   │
└─────────────────┴───────────────────────────────────┴───────────────────┘
```

## 사용법

1. 왼쪽 **프로젝트 추가**에서 `~/projects/my-app` 같은 전체 경로를 넣거나 **폴더 선택**을 누른다. Studio가 폴더를 실제 경로로 확인하고(홈 폴더 전체, 시스템·설정 폴더는 거부) **OS 확인 창**에서 **추가**를 눌러야 목록에 들어간다.
2. 메시지를 쓰고 Enter(줄바꿈은 Shift+Enter). 첫 메시지가 새 대화를 만들고 제목이 된다.
3. **받는 에이전트**
   - **Claude Opus 5.5 · medium** (기본): 그 폴더에서 `claude -p --output-format stream-json`으로 실행. 모델은 `claude-opus-5-5`, `CLAUDE_CODE_EFFORT_LEVEL=medium`으로 고정한다.
   - **Codex**: `codex exec --json`으로 실행.
   - **기획 · Reason Network**: 연결된 피어(Muse·OpenAI Dots를 추천으로 맨 위에 표시)에게 요청을 보낸다. Studio가 폴더에서 읽은 프로젝트 현황(구성, 최상위 항목, package.json 요약, README 앞부분)을 자료로 붙인다. 답장(그 요청에 대한 회신이며 보낸 피어에게서 온 것만)은 같은 대화에 기획 카드로 나타나고, **이 기획으로 구현**을 누르면 모드를 편집으로 바꾸고 Claude에게 보낼 구현 요청을 입력창에 채운다. 보내기는 직접 누른다.
   - **기획 · 호스팅 어시스턴트 (Muse · OpenAI Dots · Grok Bot)**: 이들은 Reason MCP(`list_team`, `send_message`, `check_inbox`)로만 Network에 붙고, 피어 목록에 나타나지 않으며 이름으로 메시지를 받지 못한다. 그래서 Studio는 아무것도 보내지 않고 **전달문**을 만든다. 전달문에는 요청, 프로젝트 현황, Studio 주소(`selfId`), 대화마다 새로 만든 코드(`TS-XXXXXXXXXX`)가 들어간다. **전달문 복사** 후 그 앱에 붙여넣으면, 어시스턴트가 `send_message`로 Studio에 기획을 보낸다. 첫 줄에 그 코드가 있는 메시지만 해당 대화에 기획 카드로 붙는다(대소문자 무시, 다른 대화의 코드는 무시).
   - 코드 없이 온 기획은 머리의 **받은 기획 가져오기**에서 직접 골라 붙인다. 화면은 메시지 ID만 넘기고, 보낸 사람과 본문은 Studio가 받은 메시지함에서 다시 읽는다.
   - 기획 카드의 **답장**은 그 기획을 보낸 주소에게만 `reply_to`를 달아 보낸다. 호스팅 어시스턴트는 사용자가 그 앱에서 다시 말을 걸 때 `check_inbox`로 받는다. 그 답에 대한 회신은 일반 회신 경로로 같은 대화에 붙는다.
   - 기획을 받거나 붙여도 아무것도 실행하지 않는다. 구현은 **이 기획으로 구현**으로 입력창을 채운 뒤 직접 보낸다.
4. **모드**: **기획**은 읽기 전용(Claude `--permission-mode plan`, Codex `read-only` 샌드박스), **편집**은 파일 수정(Claude `acceptEdits`, Codex `workspace-write`). 전체 권한(`bypassPermissions`, `danger-full-access`)은 어떤 경우에도 쓰지 않는다. 승인이 필요한 명령은 거부되고 그 사실이 대화에 표시된다.
5. 답하는 동안 도구 호출이 한 줄씩 쌓인다. 줄을 펼치면 입력과 결과를 본다. **중지**는 그 대화의 프로세스 그룹에 TERM, 3초 뒤 KILL을 보낸다.
6. **작업 폴더 (기존 Git worktree 연결)**: 대화 머리 아래 줄에 그 대화가 읽고 쓰는 폴더가 보인다. 첫 메시지를 보내기 전에는 **기존 worktree 연결**로, 이 프로젝트 저장소에서 `git worktree add`로 이미 만든 폴더를 OS 폴더 선택 창에서 고른다. Studio는 폴더를 실제 경로로 확인하고(심볼릭 링크는 풀어서), `git rev-parse --git-common-dir`로 **프로젝트와 같은 저장소의 공용 git 디렉터리인지**, 그 폴더가 worktree의 최상위인지, 커밋이 있는지 검사한 뒤 **OS 확인 창**(원본 폴더·worktree·브랜치·기준 커밋)에서 **연결**을 눌러야 저장한다. 원본 프로젝트 폴더 자신, 다른 저장소(이름이 같아도), git이 아닌 폴더는 거부한다. 취소하거나 거부되면 빈 대화를 남기지 않는다.
   - 대화에는 worktree 경로·브랜치·기준 커밋을 저장한다. 첫 메시지를 보냈거나(기획 요청 포함) 에이전트 세션이 생긴 뒤에는 작업 폴더를 바꿀 수 없다.
   - 그 대화의 에이전트 실행, 기획 요청에 붙는 프로젝트 현황, 변경 사항 패널은 모두 이 worktree를 쓰고, 쓰기 직전마다 같은 실제 폴더·같은 저장소인지 다시 확인한다. 폴더가 사라졌거나 링크로 바뀌었거나 다른 저장소로 교체되면 실행하지 않는다.
   - 원본 프로젝트 폴더의 staged·unstaged·untracked 변경은 건드리지 않는다. 대화를 지워도 worktree 폴더와 파일은 그대로 둔다.
   - worktree가 없는 기존 대화는 원래대로 프로젝트 폴더에서 동작한다(저장 형식에 새 필드가 없어도 읽는다).
   - 같은 작업 폴더에서 **편집** 모드 턴은 한 번에 하나만 실행한다(다른 대화가 그 폴더를 고치는 중이면 CLI를 띄우기 전에 거부). 기획 모드와 다른 폴더의 대화는 기다리지 않는다.
   - Studio는 worktree를 지우지 않는다(정리는 사용자가 `git worktree remove`로 직접).
6-1. **격리된 새 대화 (새 브랜치·worktree 자동 생성)**: 첫 메시지를 보내기 전에 **격리된 새 대화**를 누르면 Studio(native)가 만들 것을 먼저 보여 준다: 원본 폴더, 새 폴더 `<프로젝트 상위>/<프로젝트 이름>-worktrees/<대화 ID 앞 8자>`, 새 브랜치 `studio/<대화 ID 앞 8자>`, 기준 HEAD(원본의 **커밋된** HEAD). 이름은 대화 ID로 native가 만들고, 화면은 대화 ID만 넘긴다. **만들기**를 누르면 OS 확인 창이 한 번 더 뜨고, 확인 직후 같은 계획을 다시 계산해 HEAD·폴더가 바뀌었으면 만들지 않는다.
   - 생성은 셸 없이 `git -c core.hooksPath=/dev/null worktree add -b <브랜치> <폴더> <기준 커밋>` 한 번이다. 저장소 훅은 돌지 않고, `--force`는 쓰지 않는다. 화면이나 모델이 준 명령은 실행하지 않는다.
   - 마지막 커밋에서만 시작한다. 원본의 커밋하지 않은 변경, `.env` 같은 파일, 의존성은 복사하지 않고 stash도 하지 않는다. 원본 폴더의 브랜치와 파일은 그대로다. 의존성 설치·서버 실행·병합은 하지 않는다.
   - 같은 경로나 같은 이름의 브랜치가 이미 있으면 덮어쓰지 않고 이유를 보여 준다(그 폴더를 쓰려면 **기존 worktree 연결**). Git 저장소가 아닌 프로젝트, 커밋이 없는 저장소, 저장소 최상위가 아닌 프로젝트 폴더, 이미 시작한 대화도 이유와 함께 거부한다. 같은 대화에서 두 번 누르면 두 번째는 거부한다.
   - 만든 폴더는 6의 **기존 worktree 연결**과 같은 검사(같은 저장소·최상위·커밋)를 거쳐 대화에 저장되고, 브랜치와 기준 커밋이 계획과 같은지도 확인한다. 이후 고정·재검증·편집 직렬화도 6과 같다.
   - git을 부르기 전에 생성 기록을 대화 저장 폴더의 `worktree-pending.json`에 남기고, 대화에 저장한 뒤 지운다. 앱이 중간에 멈췄거나 저장에 실패하면 프로젝트 화면에 **만들다 멈춘 worktree**가 보인다. 폴더가 계획한 브랜치의 같은 저장소 worktree이면 **새 대화로 이어서 연결**(OS 확인 후)할 수 있고, 폴더가 없거나 다른 것이 있으면 안내만 보여 준다. **기록 지우기**는 기록만 지운다. Studio는 출처가 불명확한 폴더나 브랜치를 자동으로 지우지 않는다. git이 실패했는데 폴더도 브랜치도 남지 않았으면 기록을 바로 지우고 "아무것도 바뀌지 않았다"고 알린다.
7. 오른쪽 **변경 사항**은 그 대화의 작업 폴더(worktree가 있으면 worktree)의 `git status`와 `git diff HEAD`를 읽기 전용으로 보여 주며, 대화의 한 턴이 끝날 때마다 다시 읽는다.
7-1. **선택 파일 커밋 (Studio가 만든 전용 worktree만)**: 6-1의 **격리된 새 대화**로 만든 worktree(`studio/<대화 ID 앞 8자>` 브랜치, `<프로젝트>-worktrees/<같은 8자>` 폴더)에서만 변경 사항 머리에 **선택 커밋**이 보인다. 직접 연결한 worktree와 프로젝트 폴더 자체에서는 커밋하지 않는다(native가 경로·브랜치 이름을 대화 ID로 다시 계산해 확인).
   - 패널은 바뀐 파일마다 상태(A·M·D)와 파일별 diff를 보여 준다. 파일을 하나씩 고르고 커밋 메시지를 쓴 뒤 **고른 파일 커밋…**을 누르면 **OS 확인 창**(worktree·브랜치·기준 HEAD·파일 목록·메시지 첫 줄)이 뜬다. **커밋**을 눌러야 진행한다.
   - 검토할 때 native는 각 파일의 현재 내용 지문(`<모드>:<blob ID>`, 삭제는 `deleted`)과 HEAD를 함께 준다. 화면은 고른 경로와 그 지문, 검토한 HEAD, 메시지만 보낸다. native는 확인 창 전후로 작업 폴더·Studio 소유·브랜치·HEAD·staged 변경·실행 중 에이전트·각 파일 지문을 다시 확인하고, 하나라도 바뀌었으면 커밋하지 않고 **다시 검토**를 요구한다(다시 검토하면 고른 파일은 비워진다).
   - 고른 파일은 한 번만 읽어(링크를 따라가지 않음) 그 바이트가 검토한 지문과 같을 때만 저장한다. HEAD에서 시작한 **임시 index**에 그 파일들만 넣고 `write-tree` → `commit-tree` → `update-ref <브랜치> <새 커밋> <검토한 HEAD>` 순으로 만든다. 그래서 고르지 않은 파일은 커밋에 들어가지 않고, 그사이 브랜치가 움직였으면 브랜치를 바꾸지 않는다. 성공하면 worktree의 index에서도 그 파일들만 새 커밋과 맞추고, 실제 커밋 SHA와 브랜치를 패널에 보여 준다.
   - 거부: 이미 staged(git add된) 변경이 있을 때, 그 폴더에서 에이전트 턴이 실행 중일 때, 병합·리베이스·체리픽이 진행 중일 때, worktree가 다른 브랜치로 바뀌었을 때. 심볼릭 링크, 링크된 폴더 안의 파일, 하위 저장소, 5 MiB보다 큰 파일, 보이지 않는 문자나 UTF-8이 아닌 이름은 고를 수 없다. 한 번에 100개 파일, 메시지 4000바이트까지.
   - `git add .`는 쓰지 않는다. git은 셸 없이 인자로만 부르고 `core.hooksPath=/dev/null`, `core.fsmonitor=false`, `commit.gpgSign=false`, `--literal-pathspecs`, 필터·textconv·외부 diff 없이 실행한다. 저장소 훅과 서명 프로그램은 돌지 않는다(서명이 필요하면 직접 커밋한다).
   - push·원본 브랜치 반영·병합·되돌리기·hunk 단위 선택은 하지 않는다. 커밋이 실패하면 브랜치·파일·index는 그대로이고 이유를 보여 준다.
8. 다음 메시지는 같은 CLI 대화를 이어 간다(Claude `--resume`, Codex `exec resume`). 대화를 시작한 뒤에는 에이전트를 바꿀 수 없고, 새 대화를 연다.
9. 왼쪽 위 **프로젝트·대화 검색**은 프로젝트 이름과 대화 제목만 대소문자·연속 공백을 무시하고 거른다(대화 본문·코드 검색은 하지 않는다). 결과마다 프로젝트·에이전트·실행 상태를 보여 주며 ↓/↑로 이동, Enter로 열기, Esc로 지운다. 결과를 열어도 실행·중지 대상은 바뀌지 않고, 입력 중인 초안은 대화마다 따로 남는다.
10. 대화 머리 아래 **미리보기 주소**에 그 대화의 로컬 개발 서버 주소(예: `http://localhost:5173`)를 직접 넣고 **저장**한다. `http`/`https`이면서 호스트가 `localhost`, `127.0.0.1`, `[::1]`인 주소만 받는다. 아이디·비밀번호가 붙은 주소, 원격 호스트, 다른 스킴은 거부한다(화면에서 먼저 막고 Studio가 URL 파서로 다시 검사). 주소는 대화마다 따로 저장되어 재시작 뒤에도 남는다. **미리보기 열기**는 기존 `open_external` 경로로 외부 브라우저에서만 연다. Studio 창 안에서는 열지 않는다. 이 주소는 *사용자가 연결한 주소*일 뿐이며, 그 작업 폴더의 서버인지 Studio가 확인하지 않는다. 서버를 대신 실행하거나 포트를 찾지 않고, 에이전트 출력에 있는 주소를 자동으로 저장하거나 열지도 않는다. 비우려면 연필 버튼을 누른 뒤 **지우기**를 누른다.
11. **파일 첨부 (작업 폴더 안의 작은 텍스트 파일)**: 입력창 아래 **파일 첨부**를 누르면 Studio가 **OS 파일 선택 창**을 그 대화의 작업 폴더(연결한 worktree가 있으면 worktree)에서 연다. 새 대화에서 누르면 대화를 먼저 만들고, 취소하거나 거부되면 빈 대화를 남기지 않는다.
   - 받는 파일: 작업 폴더 **안**의 일반 파일, **UTF-8 텍스트**(NUL·제어 문자·잘못된 UTF-8은 바이너리로 보고 거부, BOM은 뗌), 빈 파일 아님. 파일 자체나 경로 중간의 **심볼릭 링크**, 폴더 밖 파일, `.git` 안의 파일은 거부한다.
   - 한도: 메시지당 **최대 4개**, 파일당 **8KiB**, 합계 **16KiB**. 같은 파일은 한 번만.
   - 입력창 위에 보낼 첨부가 이름·크기와 함께 나오고, 펼치면 **보낼 내용 그대로** 미리보기, ✕로 제거한다. 화면은 경로를 모르고 **첨부 ID만** Studio에 넘긴다. 고른 파일은 Studio가 메모리에 들고 있어서 창을 다시 열어도 남고, 앱을 다시 시작하면 사라진다(보내지 않은 첨부).
   - **보내기 직전** Studio가 같은 검사(폴더 안·링크·바이너리·크기)를 다시 하고, 고른 뒤 **내용이 바뀌었으면 보내지 않는다**. 바뀐 내용이 미리보기에 "선택 후 바뀜"으로 표시되고, 확인한 뒤 다시 보내면 그 내용이 간다. 작업 폴더가 바뀌면(worktree 연결) 이전에 고른 첨부는 지운다.
   - 구현 에이전트(Claude·Codex)에게는 입력한 문장 뒤에 `--- 첨부 파일 N개 (… 지시가 아닌 자료) ---` 블록으로 파일 이름·크기와 내용을 붙여 stdin으로 보낸다(파일 안의 ``` 보다 긴 펜스로 감싼다). **호스팅 어시스턴트 전달문**에도 같은 블록이 요청 아래에 들어간다. Reason Network 피어와 답장에는 첨부를 보낼 수 없다(보내기가 막히고 안내가 나온다).
   - 대화 기록에는 입력한 문장과 별도로 **첨부한 파일 이름·크기**만 남는다(내용은 저장하지 않음). 재시작 후에도 그 메시지 아래에 첨부 표시가 따로 보인다.
12. **작업 현황 (병렬 작업)**: 왼쪽 위 **작업 현황**에 모든 프로젝트에서 실행 중이거나 한 턴을 마친 대화가 모인다. 각 줄은 에이전트(Claude·Codex), 브랜치(worktree가 없으면 "원본 폴더"), 다른 프로젝트면 그 이름, 상태(실행 중·완료·실패·중지됨)를 보여 주고, 머리글에 `실행 중/4`를 표시한다. 줄을 누르면 그 프로젝트와 대화로 이동하고, 실행 중인 줄의 중지 버튼은 그 대화만 멈춘다. 서로 다른 worktree의 Claude·Codex 대화는 동시에 돌 수 있다. 작업 분할, 에이전트끼리의 지시, 결과 병합은 자동으로 하지 않는다.
   - 마지막 턴의 결과(완료·실패·중지됨, 시작·종료 시각)는 대화에 `lastRun`으로 저장되어 재시작 후에도 남는다. 예전 대화는 이 필드 없이 읽힌다.
13. **기획 요청별 답장 추적**: 한 대화에서 여러 기획 요청(피어·호스팅 어시스턴트)을 보낼 수 있고, 답장은 요청별로 짝지어진다. native가 판단한 **원 요청 item ID**를 기획 카드에 함께 저장한다(피어는 기존 `reply_to` + 보낸 피어, 호스팅은 대화 전달 코드로 연결). B의 답장이 먼저 와도 A는 계속 대기 중이며, 대화 위에 `남은 요청 N/M개`가 보인다.
   - **받은 기획 가져오기**로 코드 없이 직접 붙인 기획은 **요청 연관 미확인**으로 표시되고 어떤 요청도 닫지 않는다. 이 정보가 없는 예전 기록에 연관을 꾸며 넣지 않는다.
   - 전달문을 만들거나 복사한 것은 '전송·수신 완료'가 아니다. 전달 코드는 대화를 고르는 분류용이며 보낸 쪽의 신원을 증명하지 않는다.
   - **기획 답장 확인** 버튼으로 현재 대화의 답장을 직접 다시 확인할 수 있고, 조회에 실패하면 그 오류를 보여 준다. 답장을 받거나 상태가 바뀌어도 CLI 실행·자동 답장·원 요청 재전송은 하지 않는다.
14. **입력 초안 보존**: 입력창의 텍스트는 대화마다(프로젝트 ID + 대화 ID, 아직 만들지 않은 새 대화는 프로젝트별 키) **이 기기의 로컬 저장소에만** 저장되며, 입력 중에 "초안은 이 기기에만 저장됩니다"가 보인다. 다른 대화로 갔다 오거나 앱을 다시 열면 그 대화의 초안이 돌아온다. 복원만으로는 아무것도 보내지 않는다.
   - 보내기에 성공하면 보낸 대화의 **보낸 텍스트만** 지운다. 보내는 동안 더 쓴 내용과 다른 대화의 초안은 남는다. 전송 실패·취소에는 그대로 둔다.
   - **이 기획으로 구현**은 기존 초안을 덮어쓰지 않고 그 뒤에 이어붙인다.
   - 텍스트만 저장한다. 첨부(파일 내용·ID), 답장 대상, 에이전트·모드는 초안으로 복원하지 않는다(첨부는 기존대로 다시 고르고 확인).
   - 한도: 초안 하나는 전송 한도와 같은 **32KiB**, 전체 **256KiB**·200개. 넘거나 저장소를 쓸 수 없거나 손상됐으면 경고만 보이고 화면의 입력은 잃지 않는다. Studio에서 대화·프로젝트를 지우면 그 초안만 지운다.

### 2차 안정화(9~14)에서 바뀐 동작·제한

- **턴 시작 중 저장 실패(9)**: 턴 메타데이터나 첫 사용자 메시지를 저장하지 못하면 그 오류를 그대로 보여 주고, 띄운 CLI의 프로세스 그룹을 끝내고 자식 프로세스를 회수(최대 5초)한 뒤 실행 자리를 돌려준다. 저장하지 못한 프롬프트는 CLI stdin으로 보내지 않으며, 같은 대화에서 바로 다시 보낼 수 있다. 다른 대화의 프로세스는 건드리지 않는다.
- **diff 조회 실패(10)**: 파일의 diff를 읽지 못하면(git 실패·시간 초과·읽기 오류) '변경 없음'으로 처리하지 않고 "diff를 읽지 못해 … 커밋하지 않습니다"라는 사유와 함께 선택할 수 없게 한다. 화면이 선택을 꾸며 보내도 native가 새 검토에서 다시 거부한다. 정상적인 빈 diff, 바이너리 안내, 잘림 표시와는 구분된다.
- **대화 전환 중 늦은 응답(12)**: 기록 조회·기획 수신·전송 결과·diff 조회는 시작한 프로젝트/대화와 화면 세대를 기억하고, 그사이 화면이 바뀌었으면 현재 화면에 적용하지 않는다. 초기 조회보다 먼저 온 실시간 항목은 늦게 온 스냅샷 때문에 사라지지 않는다(item ID로 중복 제거). 떠난 대화의 오류나 초안 비우기는 그 대화에만 적용된다.
- **선택 커밋 영수증(13)**: 7-1의 선택 커밋이 성공하면 git 결과에서 가져온 SHA·브랜치·worktree·파일 목록(50개까지 이름, 나머지는 개수)·index 갱신 여부가 대화 기록에 plain-text 알림("선택 커밋 완료")으로 남는다. 패널이나 대화를 다시 열거나 앱을 재시작해도 보인다. 취소·실패에는 영수증을 남기지 않는다. 커밋은 됐는데 영수증 저장만 실패하면 **커밋 성공과 기록 경고를 함께** 보여 주며, 커밋 실패로 바꾸거나 다시 커밋하지 않는다.
- 바뀌지 않은 것: 프로젝트 폴더 확인(실제 경로·OS 확인), 같은 작업 폴더 편집 턴 직렬화, 동시 실행 4개 한도, Claude `claude-opus-5-5` · effort `medium` 고정, 전체 권한 플래그 금지, 받은 기획의 자동 구현 금지(**이 기획으로 구현**은 입력창만 채움).
- 범위 밖: 커밋 직후 강제 종료까지 보장하는 무손실 journal, 전체 Git 이력 화면, 초안 클라우드 동기화·여러 창 동시 편집, 기획 요청 취소/만료 스케줄러. Studio 밖에서 지운 대화의 초안은 남는다.

## 동작과 안전장치

- 한 턴 = CLI 프로세스 하나, 자기 프로세스 그룹. 입력한 문장은 **stdin**으로만 전달하고 명령줄에 넣지 않는다.
- 한 대화에 한 턴씩, 전체 동시 실행은 4개까지, 같은 작업 폴더의 편집 턴은 하나씩. 이 한도는 native가 지키며, CLI를 띄우기 전에 실행 자리를 먼저 잡으므로 거부된 요청은 아무 프로세스도 만들지 않는다. CLI 시작이나 턴 기록 저장에 실패하면 그 프로세스 그룹을 끝내고 자리를 돌려준다. 중지는 그 대화의 프로세스 그룹에만 신호를 보낸다. Studio를 종료하면 실행 중인 턴을 멈춘다.
- 실행 직전마다 폴더가 확인한 그 경로 그대로인지(심볼릭 링크로 바뀌지 않았는지), 연결한 worktree면 같은 저장소인지 다시 검사한다. git은 셸 없이 인자로만 부르고 `GIT_DIR` 같은 환경 변수는 지운다.
- 에이전트 출력은 신뢰하지 않는 자료다. 정해진 항목(메시지, 생각, 도구 호출·결과, 완료·오류)으로만 정리해 길이를 제한하고, 보이지 않는 문자를 지우고, HTML이 아닌 텍스트로 표시한다. 훅 출력이나 토큰 카운터는 표시하지 않는다.
- 기록은 `~/Library/Application Support/kr.toris.studio/project-chat/`(macOS)에 저장한다. 목록에서 프로젝트를 지우면 그 대화 기록만 지우고 폴더는 건드리지 않는다.
