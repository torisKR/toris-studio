# SNS 일괄 게시 · 콘텐츠 종류와 수동 인계 확장

게시 순서는 **콘텐츠 종류 선택 → 파일·공통 문구 준비 → 채널별 수정·미리보기 → 사전 검사 → 명시적 승인 → 자동 게시/예약 또는 수동 인계 → 결과 확인**입니다. 영상은 기존 YouTube, Instagram 전문 계정, Facebook Page, Threads, TikTok을 지원합니다. 텍스트는 Facebook Page·Threads 자동 게시와 네이버 수동 인계를, 블로그 원고는 네이버 수동 인계와 첨부 이미지를 지원합니다. X는 아직 연결되지 않았으며 기존 네이버 수집·채널·로그인 데이터는 유지합니다. 이 설명은 0.1.23 소스의 기능 범위이며 설치 파일 제공이 사용자의 앱 교체·운영 DB 이행 완료를 뜻하지 않습니다.

네이버 블로그·X·Instagram·Threads·Facebook·TikTok 범위는 [SNS 자동화 계획](SOCIAL_AUTOMATION_PLAN.md)을 참고하세요. 현재 구현과 후속 계획, 공식 API 제약, 수동 인계와 실제 게시 완료를 구분합니다.

## ChatGPT 초안과 에셋

코딩에서 실제 ChatGPT 대화와 Codexify를 연결하고 대화를 직접 시작하세요. 앱은 연결된 대화에 초안 요청 ID와 주제를 전달합니다. ChatGPT는 `studio_publication_draft_receive`로 제목·설명·태그·해시태그를 반환합니다. 수신된 초안은 적용·편집·저장할 수 있으며 자동 승인되지 않습니다. 이미지 생성은 기존 `studio_asset_request` / `studio_asset_receive` 경로로 요청·수신하고 게시 썸네일 선택에 사용합니다.

전달 저장, ChatGPT의 요청 수신, 답변, 파일 수신은 별도 상태입니다. 메시지 저장만으로 모델이 실행됐다고 표시하지 않습니다. 대화가 쉬고 있거나 연결이 끊겼으면 실제 ChatGPT에서 대화를 재개해야 합니다. ChatGPT 사용 한도는 그대로 적용됩니다. Open WebUI와 직접 모델 API·CLI 호출은 데스크톱에서 제거했습니다. 이전 앱 소유 컨테이너는 중지하고 대화 데이터 볼륨은 보존합니다.

## 게시 권한과 필드

| --- | --- | --- |
| YouTube | OAuth `youtube.upload`, resumable 업로드, 원격 영상 처리·조회 | 제목·설명·태그·해시태그·썸네일. 수집 API 키는 게시 권한이 아닙니다. 실제 응답의 공개 범위를 결과에 표시합니다. |
| Instagram | 전문 계정 권한, Reel 컨테이너·파일 업로드·상태 조회·게시 | 제목·설명·해시태그를 캡션으로 적용. 별도 태그는 미지원. 커버 URL 또는 영상 프레임. |
| Facebook | 관리 가능한 Page 선택, Reel 시작·파일 전송·게시·조회 | 제목·설명·해시태그. 별도 Video 썸네일 API 실패는 영상 게시 결과와 따로 표시합니다. |

| TikTok | Direct Post 또는 받은 편지함 초안, 청크 파일 업로드·상태 조회 | Direct는 캡션·공개 범위·댓글·Duet·Stitch·상업 표시·음악/게시 동의·커버 프레임. 초안은 영상만 전달하고 TikTok에서 문구·설정을 최종 확인합니다. |
| Facebook 텍스트 | 관리 가능한 Page의 feed 게시·ID 저장·게시 여부 재조회 | 제목·본문·해시태그를 message로 전송. 영상·썸네일·별도 태그는 전송하지 않으며 최종 본문은 앱 기준 10,000바이트 이내입니다. |
| Threads 텍스트 | TEXT 컨테이너·처리 상태·publish·결과 조회 | 제목·본문·해시태그를 본문으로 전송. 영상 파일·임시 미디어 터널은 불필요하며 본문 전체 길이를 검사합니다. 실제 API의 추가 제한은 응답으로 확인해야 합니다. |
| 네이버 수동 인계 | 로컬 원고/이미지 패키지 → 사용자가 네이버에서 직접 게시 → 실제 게시 URL 확인 기록 | 제목·본문·태그·해시태그 및 article의 최대 20개 등록 이미지. 계정 실재·권한·게시 성공을 API로 확인하는 경로가 아닙니다. |

TikTok 공개 Direct(예약 포함)는 개발자 설정의 심사 승인 선언, `video.publish`, 최신 creator 정보와 실제 API 허용을 모두 확인합니다. 선언만으로 API 심사를 통과했다고 표시하지 않습니다. 미심사 앱의 Direct는 비공개 계정의 `SELF_ONLY`로 제한됩니다. 내부·개인용 도구의 공개 Direct 심사는 보장하지 않습니다. 공개 범위는 사용자가 직접 선택하며 최신 계정에서 비활성화한 댓글·Duet·Stitch는 활성화할 수 없습니다. 초안 전송의 완료 상태는 **초안 전송 완료**이며 **게시 완료**로 표시하지 않습니다.

## TikTok 영상 예약·초안 사용 순서

1. **게시 콘텐츠 종류 → 영상**을 선택하고 등록한 MP4와 편집 가능한 문구를 준비합니다. 이 릴리스는 TikTok 텍스트·사진 게시를 지원하지 않습니다. 공식 API의 사진 기능까지 앱에 구현됐다는 뜻은 아닙니다.
2. **계정 조회 → TikTok → 게시 계정**을 선택합니다. Direct는 `video.publish`, 받은 편지함 초안은 `video.upload`에 대한 앱 승인과 사용자 권한이 필요합니다. 계정의 최신 creator 정보·최대 영상 길이를 확인하고 로그인 성공을 게시 권한으로 간주하지 않습니다.
3. 사용자가 TikTok에서 마무리하려면 **TikTok 초안 전송**을 선택합니다. 문구·공개 범위·커버는 Direct 설정으로 전송하지 않으며 TikTok 알림에서 사용자가 확인·편집·최종 게시합니다. 초안 전송은 자동 예약 일괄 적용에서 제외됩니다.
4. Direct는 **수동 · 승인 후 즉시** 또는 **자동 · 승인한 예약**을 선택하고 공개 범위를 직접 고릅니다. 미심사 앱에서는 비공개 계정의 `SELF_ONLY`만 사용합니다. 공개 범위는 기본 선택하지 않으며 댓글·Duet·Stitch도 기본 해제합니다. 음악 사용 확인·필요한 상업 콘텐츠 표시·전송 동의를 검토합니다. 유료 파트너십은 `SELF_ONLY`와 함께 사용할 수 없습니다.
5. Direct 예약은 KST 일시를 직접 입력하거나 **채널 예약 시간을 한 번에 설정**을 사용합니다. 공개 범위를 자동으로 공개로 바꾸지 않습니다. 비공개 예약도 실행 시점의 권한·creator 조건을 충족해야 합니다. 초안 저장 → 사전 검사 → 표시된 대상·파일·문구·시간의 최종 승인 전에는 전송 작업이 만들어지지 않습니다.
6. Direct의 업로드 수락은 **플랫폼 처리 중**, 받은 편지함 전달 확인은 **초안 전송 완료**, 실제 게시 완료 API 응답은 **게시 확인됨**으로 구분합니다. 원격 ID를 먼저 저장하고 결과가 불명확하면 같은 ID를 조회하며 새 전송을 반복하지 않습니다.

공식 지침 확인: 2026-10-19, [Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines) 및 [Upload guide](https://developers.tiktok.com/doc/content-posting-api-get-started-upload-content). 계정·앱 심사 상태는 실제 연결 시 다시 확인해야 합니다. 로컬 테스트는 실제 TikTok 계정 게시를 수행하지 않습니다.

## 승인과 예약 복구

작성 화면의 **채널 예약 시간을 한 번에 설정**에서 시작 시각(KST)과 채널 사이 간격(0~1440분 정수)을 입력하고 **예약 시간을 초안에 적용**하세요. ‘이번에 검사·승인할 대상’ 중 자동 게시 가능한 채널에 화면 순서대로 적용하며, 0분은 같은 예약 시각입니다. 수동 네이버 인계와 TikTok 초안 전송은 제외합니다. 실제 게시 완료 시각은 플랫폼 처리 시간에 따라 달라집니다. 적용만으로 저장·승인·게시하지 않으며 기존 사전 검사와 최종 동의는 해제됩니다. **초안 저장 → 사전 검사 → 최종 승인**을 다시 진행하세요. 잘못된 날짜·지난 시각·중복 대상·현재 버전에서 이미 승인/전송한 대상은 거부합니다. 이 기능은 한 콘텐츠의 여러 채널 예약 편집이며 여러 콘텐츠 배치 등록과 반복 일정은 후속 범위입니다.

PostgreSQL `publications`의 수정 버전과 채널별 문구·계정·방식, `publication_jobs`의 승인 파일 SHA256·실행 결과를 영구 저장합니다. 가져온 파일은 앱 전용 폴더에 복사하고 사용 시 해시를 재검증합니다. 초안을 수정하면 이전 예약 승인은 취소되며 새 사전 검사·승인이 필요합니다. 기존 일정 기록은 편집 가능한 미승인 초안으로 이행하고 실행 작업을 생성하지 않습니다.

채널별 결과는 **대기 / 예약 / 전송 / 처리 중 / 게시 완료 / 수동 게시 필요 / 초안 전송 완료 / 결과 불명확 / 재확인 필요 / 실패 / 취소**로 구분합니다. 성공한 채널은 다시 전송하지 않습니다. 네트워크 단절 등으로 결과가 불명확하면 새 업로드를 만들지 않고 기존 원격 ID로 조회합니다. 원격 ID 자체가 없으면 해당 SNS에서 사용자가 직접 게시 여부를 확인한 뒤 결과를 기록하거나 미게시로 확인하고 다시 승인합니다. 확인만으로 재게시하지 않습니다.

앱 창을 닫으면 프로세스는 메뉴 막대·트레이에 남습니다. **열기 / 예약 일시정지 / 재개 / 완전히 종료**를 제공합니다. 게시 전송·원격 미디어 처리 중에는 종료와 업데이트를 보류합니다. 완전 종료·절전으로 놓친 예약은 자동으로 밀어 올리지 않고 재승인을 요구합니다. PC 전원·인터넷·로컬 PostgreSQL이 실행 중이어야 예약이 실행됩니다.

Threads 영상 및 필요한 Instagram 커버는 예측 불가능한 URL의 임시 터널에 승인한 파일만 제공합니다. 디렉터리·MCP·다른 로컬 파일은 노출하지 않습니다. 처리 완료·실패·최대 2시간 만료 시 터널을 폐기합니다. OAuth 토큰·클라이언트 시크릿은 OS 저장소에 유지하고 DB·IPC 결과에는 넣지 않습니다.

## 텍스트·네이버 원고 사용 순서

1. 콘텐츠 작성에서 **게시 콘텐츠 종류**를 선택합니다. `텍스트`는 Facebook Page·Threads·네이버를, `블로그 원고`는 네이버와 첨부 이미지 영역을 표시합니다. 종류 변경은 비호환 대상/파일 연결을 해제하며 파일 원본은 보존합니다.
2. 공통 문구와 채널별 문구를 확인합니다. Facebook Page·Threads는 계정 조회 후 실제 게시 대상과 공개 동의를 직접 선택합니다. 블로그 원고 이미지는 PNG·JPEG·WebP의 등록 복사본 중 최대 20개를 선택합니다.
3. 네이버는 주소·비밀번호가 아닌 **블로그 ID**를 입력하고 **자동 게시가 아닌 네이버 수동 게시 인계임을 확인했습니다**를 체크합니다. 로그인 성공이나 ID 입력을 API 게시 권한으로 표시하지 않습니다.
4. 초안 저장 → 사전 검사 → 최종 확인 → **선택한 대상 일괄 승인**을 진행합니다. 네이버는 `수동 게시 필요`에 남으며 자동 전송/예약을 실행하지 않습니다.
5. 예약·게시 이력에서 **인계 자료 내보내기**를 눌러 저장 폴더를 직접 선택합니다. 새 `toris-naver-<UUID>` 폴더에 title.txt, body.txt, tags.json, manifest.json, README.txt와 이미지가 있으면 images/를 생성합니다. 승인 이미지가 바뀌면 실패하며 기존 내보내기 폴더를 덮어쓰지 않습니다. 내보내기 취소/완료 모두 게시 완료가 아닙니다.
6. 네이버 편집기에서 직접 게시하거나 예약합니다. 예약만 설정했다면 Studio에서 완료로 기록하지 않습니다. 실제 공개된 개별 게시글을 확인한 뒤 **수동 게시 완료 기록**에서 해당 블로그의 HTTPS URL과 사용자 확인을 입력합니다. 다른 블로그·홈·가짜 호스트 URL은 거부하며 결과에는 **사용자 직접 확인 · API 검증 아님**을 표시합니다.
7. 원고 수정/취소 후에는 이전 승인의 인계 자료를 다시 내보낼 수 없습니다. 새 사전 검사·승인이 필요합니다.

DB 변경은 `008_publication_handoffs`이며 앱의 기존 DB 이행 경로와 `scripts/db-migrate.ts`에 포함했습니다. 릴리스 설치 파일 제공과 운영 DB 적용·스케줄 활성화·실제 계정 게시·설치 앱 교체는 별도 작업입니다. 이 기능 검증에서는 후자의 운영 작업을 수행하지 않았습니다.

## 검증 범위

Rust fixture 테스트로 API 단계, 범위·계정 검증, 업로드·조회, TikTok 초안과 실제 게시 구분, 중복 방지 및 제한을 검사합니다.
Facebook Page·Threads 텍스트도 원격 ID 저장/재조회와 모호한 commit 재실행 금지를 fixture로 검사합니다. `node scripts/verify-publication-db.mjs`는 별도 임시 PostgreSQL로 기존 행을 가진 migration 재적용, 수동 인계 SQL 제약·사용자 확인·큐 복구를 검사하고 종료/삭제합니다. Homebrew PostgreSQL 17 기본 경로를 사용하며 다른 설치는 `TORIS_TEST_PG_BIN`으로 지정합니다. 앱 자격 증명·기존 DB에는 연결하지 않습니다. Chromium의 `scripts/verify-publication-ui.mjs`는 명시적 IPC fixture이며 실제 네이버 게시나 OS 폴더 선택 대화상자의 성공 증거가 아닙니다. 별도 임시 PostgreSQL 통합 테스트로 DB 이행·재실행 복구·수정 충돌·실행 claim을 검사합니다. 실제 계정 게시 성공은 사용자 승인 콘텐츠로 API 결과를 확인한 경우에만 주장합니다. 로컬 fixture 통과나 설치 파일 빌드는 실제 SNS 게시 또는 Windows 기기 실행 검증을 대신하지 않습니다.
