# Toris Studio — AI 중심 에셋 제작 운영 설계

작성일: 2026-10-09
상태: 대화에서 제품 방향 승인됨. 이 문서는 구현 전 검토본이며, 작성된 기능이 이미 구현되었다는 뜻이 아니다.
대상: `/Users/toris/projects/toris_studio`의 기존 Tauri 데스크톱 앱
이번 범위: AI 작업 관리 + 프로젝트 기본값 + 에셋 제작·규격 검증·결과 묶음

## 1. 목적과 성공 기준

Toris는 사람이 화면마다 폼을 작성하는 도구가 아니라, ChatGPT에 제작 목표를 전달하면 AI가 필요한 도구를 사용하고 Studio가 실행·결과·예외를 관리하는 작업실을 원한다. 이미지 생성에 Codex 구독 호출이나 별도 유료 이미지 API를 자동 추가하지 않는다. 기존 이미지·3D·영상·SNS 기능, 저장 원본, 31개 출력 규격은 유지한다.

핵심 사용 흐름은 `목표 전달 → 프로젝트 자료 확인 → 제작 계획 → 실행 → 검증 → 결과 묶음`이다. 최초 연결과 프로젝트 접근 설정 후, 정상적인 작업에는 개별 규격 선택, 요청 복사, 생성 파일 수동 연결을 요구하지 않는다. 사용자 개입은 자료 누락, 접근 승인, 정책 충돌, 실패 복구처럼 실제로 필요한 경우에만 발생한다.

완료의 기준은 버튼·카드가 생기는 것이 아니라 다음 두 시나리오의 성공이다.

1. 기존 로고로 favicon과 광고 출력 세트를 요청하면, AI가 등록된 원본을 선택하고 Studio가 규격별 파일과 검증 내역을 생성한다. 사용자는 결과 묶음만 확인한다.
2. 새 이미지가 필요한 작업은 ChatGPT가 제공되는 이미지 생성 기능을 사용하고 결과를 MCP로 전달한다. Studio는 실제 파일 수신 후에만 후속 변환을 실행한다. 생성 기능 미지원·대화 종료·사용 제한이면 사실대로 대기 상태를 보존한다.

두 번째 시나리오는 실제 사용자 ChatGPT 연결·파일 전달 검증을 통과해야 완료로 보고할 수 있다. 로컬 테스트만 성공한 상태를 전체 자동화 완료로 표현하지 않는다.

## 2. 현행 코드와 유지할 경계

이번 설계에서 확인한 기준 파일은 다음과 같다.

## 3. 범위 결정

### 이번에 포함

프로젝트별 브랜드·자료·출력 기본값, ChatGPT에서 사용하는 작업 묶음 도구, DAG 기반 단계 관리, 로컬 실행기, 중단·재개·멱등성, 파일 수신과 결과 연결, 결과 묶음·예외 중심 화면, 실제 상태 기반 마이크로 인터랙션을 하나의 에셋 제작 흐름으로 구현한다. DAG는 단계 사이의 선행 조건을 표현하는 비순환 작업 그래프이다.

### 이번에 제외

영상·TTS·SNS 게시를 새 실행기로 이관하는 작업, 계정 생성·로그인 자동화, 운영체제 로그인 시 상주 서비스 설치, 새로운 유료 모델 공급자, ChatGPT 브라우저 자동 조작·비공개 API 역호출, 무제한 이미지 생성, 임의 형상의 AI 3D 복원, 앱 화면 자동 촬영, 외부 공개 게시, 자동 파일 삭제·덮어쓰기는 제외한다.

기존 영상·음성·콘텐츠 도구는 그대로 열 수 있다. 결과물의 통합 데이터 모델은 향후 영상 연결을 수용하되, 이번 결과 화면은 에셋 작업만 통합하며 미연결 영상 결과가 나타난다고 약속하지 않는다.

## 4. AI와 로컬 실행기의 역할

**ChatGPT:** 자연어 목표 해석, 프로젝트 자료 조회, 사용할 원본 선택, 출력 목적별 구도 판단, 필요 시 이미지 생성, 결과에 대한 근거 있는 시각 검토를 수행한다. Studio 내부에 자연어를 이해하는 것처럼 보이는 규칙 기반 가짜 AI를 두지 않는다.

**Studio:** 허용된 작업을 검증·접수하고 로컬 변환·파일 검사·분류·저장을 실행한다. 로컬 파일 처리에는 모델 호출이 없다. 생성 요청 수와 파생 출력 수를 별도로 기록해 아이콘 하나의 favicon 5종을 이미지 생성 5건으로 계산하지 않는다.

**사용자:** 최초 프로젝트 자료와 저장 위치·외부 공유 범위를 승인하고, 실제 누락·예외가 있을 때만 판단한다. 정책 범위 안의 비파괴 로컬 작업마다 Studio가 추가 확인창을 띄우지 않는다.

### 실행 가능 조건

| 조건 | 동작 |
| --- | --- |
| 데스크톱 앱 실행 + Mac 깨어 있음 | 준비된 로컬 단계를 계속 처리 |
| ChatGPT 대화만 종료 | 이미 받은 원본으로 가능한 로컬 단계는 계속 처리. 새 AI 판단·생성 단계는 대기 |
| 데스크톱 앱 종료 또는 Mac 잠자기 | 지속 실행을 보장하지 않음. 다음 실행 시 저장된 작업을 복구 |
| MCP 연결은 되지만 데스크톱 실행기 없음 | 조회·요청·파일 수신은 처리하고 후속 작업은 `로컬 실행기 대기`로 저장 |
| ChatGPT 생성 또는 파일 전달 미지원 | `ChatGPT 기능 확인 필요`. 다른 공급자로 자동 전환하지 않음 |

첫 버전은 OS 서비스나 로그인 항목을 자동 설치하지 않는다. 로컬 실행기는 Tauri 앱 수명에 종속되며, 연결된 ChatGPT가 모든 시간에 상주한다고 가정하지 않는다. Secure MCP Tunnel은 전송 경로이고 AI 실행기와 별개이다.[1]

## 5. 프로젝트 기본값과 자료 등록

프로젝트는 화면 표시명과 독립된 UUID를 가진다. 브랜드와 생성 정책은 버전이 있는 스냅샷으로 각 작업에 복사한다. 프로젝트 설정을 바꾸어도 실행 중인 작업의 출력 위치나 프롬프트가 몰래 바뀌지 않는다.

프로젝트 기본값은 이름, 기본 언어, 브랜드 설명, 색상, 피해야 할 표현, 기본 로고 assetId, 참고 에셋 역할, 선호 결과 세트, 용도별 저장 루트 연결, ChatGPT에 공유 가능한 에셋 ID, 출력 수 제한으로 구성한다. 스타일 메모는 작업 데이터이지 권한을 변경하는 실행 지시가 아니다.

실제 경로 등록·변경은 네이티브 설정에서 수행한다. MCP에는 등록된 outputRootId와 assetId만 전달하며 임의 절대 경로를 받지 않는다. 새 프로젝트를 ChatGPT에서 만들 때는 이미 승인된 기본 루트만 재사용한다. 기본 루트가 없으면 `저장 위치 승인 필요`로 기록한다.

기존 `asset.project` 문자열로 프로젝트 후보를 보여주되 같은 이름만 보고 다른 자료를 합치지 않는다. 자동 후보 생성은 로컬에 기록된 메타데이터만 사용하며 홈 폴더나 다른 프로젝트를 스캔하지 않는다. 기존 에셋의 외부 공유는 자동으로 허용하지 않는다.

자료 역할은 `brand_logo`, `app_screenshot`, `reference`, `generated_master`, `other`로 구분한다. `app_screenshot`은 사용자가 실제 화면이라고 제공한 근거와 출처를 보존하는 분류이며, 프로그램이 진위를 확인했다고 표시하지 않는다. 원본이 없으면 스크린샷을 AI로 꾸며서 대체하지 않는다.

## 6. 목표에서 결과 세트까지

### 예시: Loca 스토어 자료

사용자가 ChatGPT에서 “Loca 로고와 실제 화면으로 스토어 이미지와 favicon을 준비해줘”라고 요청한다. ChatGPT는 프로젝트와 에셋 역할을 조회하고 실제 필요한 이미지 미리보기를 확인한 뒤 역할별 원본과 출력 규격을 포함한 계획을 제출한다.

아이콘과 favicon은 동일한 브랜드 원본을 사용할 수 있다. 그래픽 이미지는 별도 구도나 마스터 생성이 필요할 수 있다. 스크린샷은 제공된 실제 캡처만 사용한다. 같은 파일을 모든 비율로 무조건 자르지 않는다. 계획에는 각 출력의 `sourceRole`, `sourceAssetId 또는 선행 생성 단계`, `presetId`, `fit`, `background`, `required`가 명시되어야 한다.

### 기본 결과 세트

| 세트 | 기본 산출물 | 원본 사용 기준 |
| --- | --- | --- |
| Play 등록 준비 | 아이콘·그래픽 + 휴대전화 스크린샷 4개 | 스크린샷 4개는 제품 기본값이며 공식 필수 장수 주장 아님. 각 캡처가 있어야 해당 분기 진행 |
| 웹 아이콘 | 기존 favicon 프리셋 5개 | 하나의 승인된 로고 원본에서 파생 |
| 앱 캠페인 | 기존 캠페인·풀스크린 프리셋 4개 | AI가 구도 재사용 가능 여부를 판단하고 원본 매핑 |
| 광고 배너 | 기존 AdMob 배너 프리셋 6개 | 규격 충족과 지면 심사 통과를 구분 |
| 전면 이미지 | 기존 스마트폰·태블릿 전면 프리셋 4개 | 비율별 원본 또는 명시적인 전체 보존 정책 |
| 사용자 지정 | 기존 프리셋에서 선택한 결과 | MCP에서 한 계획으로 여러 결과를 등록 가능 |

세트는 각각 독립 실행도 가능하고 하나의 작업에 조합할 수도 있다. 기본 정책은 누락 자료가 있는 분기만 막고 원본이 준비된 분기는 진행하는 것이다. 필요한 산출물이 빠진 상태는 전체 완료가 아니다.

수정 요청은 기존 결과를 덮어쓰지 않는 새 작업 revision으로 만든다. 같은 요청의 전송 재시도와 의도적인 새 버전 제작은 구분한다.

## 7. 작업·단계·결과 데이터 모델

| 개념 | 필요한 데이터·불변 조건 |
| --- | --- |
| ProjectProfile | UUID, displayName, revision, brand, sourceBindings, approvedRootIds, sharingPolicy |
| ProductionRun | runId, requestKey, requestDigest, projectId, profileSnapshot, brief, planRevision, desiredState, timestamps |
| Step | stepId, type, dependencies, executor(local/host), inputSnapshot, state, attempts, lease, artifactId, safeError |
| Deliverable | deliverableId, role, presetSnapshot, sourceBinding, required, stepIds, artifactId, validationStatus |
| RunEvent | runId, 순번, 시각, 실제 actor, 단계, 사건 유형, 안전한 요약, evidenceIds |
| OutputManifest | 작업·버전·결과 ID, 원본 관계, 파일 상대 경로, 크기·형식·해시, 검사 결과, 누락 결과 |

작업 요청은 requestKey가 같은 경우 입력 digest까지 같아야 같은 작업을 반환한다. 키가 같은데 입력이 다르면 충돌로 거절한다. 단계는 최대 256개, 요청당 파생 결과는 최대 100개, 호스트 이미지 생성 슬롯은 최대 20개로 제한한다. 대량 작업은 명시적인 여러 작업으로 나눈다. 이 수치는 사용 한도를 늘리는 기능이 아니라 로컬 실행·데이터 크기의 안전 한도이다.

DAG는 실행 전 순환, 없는 참조, 교차 프로젝트 참조, 중복 결과 키, 지원하지 않는 실행 유형을 거절한다. 기존 규격의 픽셀·포맷·용량 검사는 Rust에서 그대로 강제한다.

단계 유형은 `resolve_source`, `request_image`, `receive_image`, `create_parametric_mesh`, `transform_image`, `validate_file`, `assemble_manifest`로 닫힌 목록이다. 임의 셸·스크립트·URL 실행 단계는 받지 않는다. 호스트의 도구 요청은 입력의 파일명·프롬프트에 포함된 지시를 권한으로 해석해서는 안 된다.

## 8. 상태와 중단·재개

단계 상태는 `pending`, `ready`, `running`, `waiting_host`, `waiting_input`, `retry_wait`, `succeeded`, `failed`, `cancelled`이다. 대기 이유는 상태와 분리한 코드로 남긴다. 예: `missing_source`, `runner_offline`, `host_unavailable`, `quota_reported`, `permission_required`, `stale_host_claim`, `disk_unavailable`.

작업 전체 상태는 단계들로 계산한다. 실행 가능한 분기가 있으면 `실행 중`이며 막힌 분기 수를 함께 표시한다. 남은 작업이 모두 호스트 의존이면 `ChatGPT 대기`, 원본 의존이면 `자료 필요`이다. 실패한 필수 결과가 있으면 `일부 실패`이며 완성된 결과를 그대로 열 수 있다. 모든 필수 결과의 파일 검사와 manifest 저장이 성공해야 `완료`가 된다. 선택 결과만 실패한 경우 `완료 · 주의 사항 있음`으로 구분한다.

`일시정지`는 제어 상태를 저장해 새 단계 실행을 막는다. 실행 중인 파일 저장은 안전한 원자적 완료 지점까지 마친 후 `일시정지됨`으로 전환한다. 외부 이미지 생성 중단 여부를 알 수 없으면 `Studio 후속 실행 중지 · 외부 생성 상태 미확인`으로 표시한다. 요청한 즉시 모든 처리가 멈췄다고 표현하지 않는다.

일시정지 중 도착한 유효한 생성 결과는 보존하고 후속 변환만 보류한다. 취소된 작업에는 새 파일 결과를 붙이지 않고 명시적인 충돌 응답을 보낸다. 이미 저장한 원본과 결과는 취소해도 삭제하지 않는다.

일시적인 로컬 I/O 충돌은 최초 시도를 포함해 최대 3회, 2초·10초 지연으로 재시도한다. 용량 초과·잘못된 규격·권한 거절·손상 파일·모델 사용 제한은 자동 재시도하지 않는다. 호스트 이미지 생성은 애매한 타임아웃만으로 재요청하지 않는다. 마지막 시도와 실패 이유를 남겨 중복 생성·반복 비용을 막는다.

사용자의 `실패 단계 재시도`는 선택한 실패 단계의 새 attempt를 만들고 후속 의존 단계만 다시 준비한다. 완료된 다른 단계는 재실행하지 않는다. 사용자가 원본을 교체하는 경우는 단순 재시도가 아니라 새 계획 revision이다.

## 9. 저장·실행·복구 설계

### 색인과 마이그레이션

에셋·프로젝트·작업 상태를 동일한 트랜잭션으로 보존하기 위해 기존 `library.json`을 version 2로 확장한다. 기존 assets/jobs/settings를 손실 없이 옮기고 projects/runs/events를 추가한다. 원본과 출력 파일은 이동하지 않는다.

최초 변경 전 기존 JSON의 바이트·해시를 확인해 중복되지 않는 v1 백업을 만든다. 마이그레이션은 현재 파일 잠금 안에서 임시 파일 작성·동기화·원자적 교체로 수행한다. 손상된 색인은 초기화하지 않고 중단한다. v1만 이해하는 기존 바이너리는 v2를 거절하므로, 새 앱과 MCP 워커를 함께 갱신해야 한다. 이전 바이너리의 덮어쓰기를 허용하기 위해 version 검사를 제거하지 않는다.

기존 API의 assets/jobs/settings 응답은 유지한다. 기존 `project` 표시 문자열도 보존하고 선택적인 projectId/runId 관계를 더한다. 구형 단독 에셋은 `기존 자료`로 조회할 수 있으며 임의로 새 작업 성공 기록을 만들지 않는다.

### 짧은 잠금과 원자적 완료

색인 잠금 아래에서 `단계 claim + attempt 저장`만 수행한 뒤 잠금을 해제한다. 이미지 디코딩·리사이즈·네트워크 수신을 잠금 안에서 기다리지 않는다. 저장 전 다시 잠금을 잡고 attempt 소유권, 계획 revision, 제어 상태를 재검사한다.

로컬 실행기는 OS 파일 잠금으로 한 프로세스만 선출하며 동시 이미지 변환은 기본 1개이다. 추가 앱 창이나 MCP 호출이 같은 단계를 중복 실행할 수 없다. 실행기 heartbeat는 5초, 관찰값이 20초 넘게 갱신되지 않으면 UI에서 `응답 확인 중`으로 표시하되 heartbeat만으로 다른 실행기를 강제 탈취하지 않는다. 소유권은 실제 OS 잠금으로 결정한다.

각 산출물은 `(runId, planRevision, deliverableId)`로 고유한 출력 디렉터리를 갖는다. 작업 전용 임시 위치에 파일과 해시 receipt를 작성하고 검증한 후 원자적으로 확정한다. 그다음 색인에 artifact와 step 완료를 함께 기록한다. 확정 직후 앱이 종료되어 색인 기록이 누락되면, 재시작 시 작업 receipt와 입력 digest를 대조해 기존 결과를 연결한다. 파일을 다시 생성해 중복 결과를 만들지 않는다.

manifest도 실제 파일·검사 결과를 기준으로 작성한다. 절대 경로를 외부 결과 보고에 불필요하게 노출하지 않고, UI의 명시적 경로 보기·복사에서만 표시한다. 저장 디렉터리와 symlink의 최종 실제 경로가 승인 루트 안인지 확정 직전에도 확인한다.

### 호스트 작업의 소유권

새 생성 슬롯에는 하나의 유효한 host claim만 허용한다. claim 유효 기간은 15분이며 임의의 AI 이름은 인증 증거가 아니다. 실제 소유권은 인증된 연결과 서버가 발급한 불투명 토큰으로 확인한다. 토큰은 로그나 화면에 노출하지 않는다.

기한이 끝나면 `호스트 확인 필요`로 전환한다. 기존 생성이 끝났는지 확인 없이 새 이미지를 자동 생성하지 않는다. 늦게 도착한 결과는 새로운 claim 확인 후 동일 슬롯에 이어 붙일 수 있지만, 취소·다른 결과로 완료·새 revision이 된 슬롯에는 붙이지 않는다. 동일 슬롯·동일 파일 해시 재전달은 기존 결과를 반환한다.

초기 호스트 결과는 규격 변환 전 원본 master로 보존한다. 작은 favicon 출력을 생성 master로 사용하지 않는다. master와 각 파생 이미지의 관계를 manifest에 남긴다.

## 10. MCP와 네이티브 인터페이스

기존 에셋 MCP 8개를 유지하고 AI 운영용 상위 도구를 추가한다. 새 도구는 다음 책임을 갖는다. 이름·필드의 상세 타입은 이 설계를 승인한 뒤 구현 계획에서 고정한다.

| 상위 도구 | 책임 |
| --- | --- |
| `studio_project_context` | 프로젝트 후보·기본값·허용 자료·결과 세트·실행 가능 기능 조회 |
| `studio_project_save` | 브랜드·언어·등록된 assetId 역할 등 비보안 기본값 저장. 경로·접근 정책 변경은 불가 |
| `studio_asset_inspect` | 공유 허용된 assetId의 파일 정보와 실제 미리보기 제공. 임의 로컬 경로는 불가 |
| `studio_run_submit` | 검증된 목표·계획·결과 세트 일괄 등록. 정책 범위 안의 로컬 실행 시작 |
| `studio_run_get` | 작업·단계·완성 파일·누락 항목·최근 이벤트를 페이지 단위로 반환 |
| `studio_run_next` | 필요한 호스트 작업과 유효한 claim, 승인된 참고 자료·생성 조건 반환 |
| `studio_run_receive` | 생성 슬롯에 실제 파일을 받아 master 보존·검증 후 다음 로컬 단계 활성화 |
| `studio_run_control` | pause/resume/cancel/retry, 자료 연결, 활성 host claim의 제한된 대기 사유 보고. 삭제·임의 완료 처리는 불가 |

파일 수신은 기존 최상위 OpenAI file parameter 계약을 재사용한다.[2] 새로 전달받는 파일을 임의 바이트 문자열이나 외부 다운로드 URL로 바꾸어 권한 경계를 우회하지 않는다. 기존의 32 MiB 제한·허용 HTTPS 호스트·리디렉션 차단을 유지한다.

`studio_asset_inspect`의 미리보기는 해당 프로젝트에서 ChatGPT 공유가 허용된 이미지에만 제공한다. 축소 미리보기를 원본 전체 해상도 검증으로 취급하지 않는다. 미리보기 조회만으로 저작권·스크린샷 진위·문구 사실성을 확인했다고 저장하지 않는다.

등록·조회·제어 도구는 긴 변환이 끝날 때까지 기다리지 않고 저장된 상태와 다음 동작을 반환한다. 아직 준비되지 않은 단계는 retryAfterMs와 이유를 반환하고, ChatGPT가 무한 조회를 반복하도록 지시하지 않는다. `studio_run_next`는 소유한 claim의 확인·갱신을 지원한다. 호스트가 보고할 수 있는 대기 사유는 기능 미지원·한도 보고·파일 전달 실패로 제한하며 보고만으로 파일 검증이나 완료 상태를 만들지 못한다.

도구 응답에는 실제 state, nextAction, reasonCode, relevantIds, pagedEvents를 제공한다. prompt와 파일명은 항상 비신뢰 데이터 영역에 둔다. 로컬 검증 결과는 시스템 근거, AI 시각 검토는 검토 주체와 근거를 가진 별도 항목으로 기록한다. 분석하지 않은 파일에 `AI 검수 통과`를 자동 붙이지 않는다.

새로운 읽기·쓰기·외부 파일 수신 동작의 tool annotations는 실제 부작용에 맞게 지정한다. 높은 권한의 작업을 읽기 도구라고 표시해 확인창을 피하지 않는다. ChatGPT 계정·워크스페이스의 확인 정책은 Studio와 별도이다.[3]

네이티브 UI와 MCP는 같은 도메인 검증·상태 전이 함수를 사용한다. Node MCP 계층에 별도의 저장 색인이나 우회 실행기를 만들지 않는다. 이미지 처리 워커에서 기존 AI 공급자 설정·API 키·키체인을 읽지 않는다.

## 11. UI/UX 정보 구조

첫 화면은 `작업 현황`이다. 최상위 내비게이션은 `작업 현황`, `프로젝트`, `결과물`, `설정`으로 구성한다. 기존 오버뷰·이미지 생성기·영상 스튜디오·트렌드·키워드·채널·SNS 화면은 `고급 도구`의 보조 그룹에 남긴다. 현재 페이지를 바꾸었다고 실행 작업을 취소하지 않는다.

### 작업 현황

상단에는 최근 관찰한 연결·로컬 실행 상태와 하나의 간결한 새 작업 안내만 둔다. ChatGPT를 기본 지시 창으로 사용하므로 앱 안에 작동하지 않는 AI 채팅 입력창을 추가하지 않는다. 연결된 기본 ChatGPT 화면을 여는 동작과 최초 설정 안내를 제공하며, 작업마다 복사·붙여넣기를 정상 경로로 만들지 않는다.

본문은 `개입 필요`, `진행 중`, `최근 완료` 순서이다. 개입할 일이 없으면 빈 경고 상자를 크게 띄우지 않는다. 작업 행에는 목표, 프로젝트, 실제 완료 결과 수, 현재 단계·대기 이유, 마지막 갱신 시각을 표시한다. 임의의 성공률·토큰 잔량·예상 완료 시각은 표시하지 않는다.

진행 정도는 `완료한 결과 3 / 필요한 결과 8`처럼 사실로 표현한다. 외부 생성 시간이 불명확한 상태를 시간 기반 70%로 꾸미지 않는다. 큰 실행 그래프는 기본 화면에 두지 않고 작업 상세의 기술 정보에서만 펼친다.

### 작업 상세

상단에 목표·프로젝트·결과 요약·정지 상태를 표시하고, 중앙에 산출물, 옆 영역에 예외·간결한 이벤트 기록을 배치한다. `일시정지`, `재개`, `실패 단계 재시도`, `새 수정 요청`은 현재 상태에서 가능한 동작만 활성화한다. 완료 파일은 일부 분기가 대기 중이어도 열 수 있다.

부족한 스크린샷은 어느 역할의 자료가 부족한지 표시하고, 연결된 기존 assetId를 선택하거나 승인된 파일 가져오기 한 번으로 해결하도록 한다. 새로운 폴더 접근이 필요할 때만 네이티브 승인으로 이동한다.

### 결과물

작업별 묶음과 프로젝트별 에셋 보기를 전환한다. 묶음에는 썸네일, 생성 master와 파생 결과의 구분, 규격, 실제 파일 검사 결과, 누락 산출물을 표시한다. `기술 규격 통과`와 `브랜드·내용 검토됨`은 독립된 상태이다. 기존 즐겨찾기·태그·크기 변경·파일 위치 열기는 유지한다.

### 프로젝트와 설정

프로젝트 화면은 브랜드·자료·기본 결과 세트를 요약하고 변경 시 새 revision이 이후 작업에 적용됨을 알린다. 저장 위치와 외부 공유 허용 범위는 설정 영역에서 명시적으로 수정한다. 실행기 관찰 성공, MCP 도구 왕복 성공, ChatGPT 생성 파일 수신 성공을 서로 다른 시간 기록으로 표시한다.

`로컬 실행 중`은 ChatGPT 연결 성공을 의미하지 않는다. 최초 연결 미확인 상태에서는 검증된 시각이 없다고 그대로 표시한다. 단순 모델 이름·실행 프로세스 존재만으로 계정 인증·이미지 생성 기능을 확인했다고 주장하지 않는다.

## 12. 시각 언어와 마이크로 인터랙션

기존 charcoal 배경, 파란 강조색, 사용자 로고, 시스템 한글 글꼴을 유지한다. 전체 브랜드를 다시 만들지 않고 수동 폼 중심 정보 계층을 결과 중심으로 바꾼다. 본문 14px, 보조 정보 12px 이상을 기본으로 하며, 작은 장식 영문과 카드를 중첩한 구조를 줄인다. 접근 가능한 글자 대비·키보드 포커스·상태 설명을 유지한다.

| 이벤트 | 동작 규칙 |
| --- | --- |
| 요청 전송 | 즉시 `전송 중`을 표시. 서버 접수 ACK 이전에는 등록된 작업·실행 중이라고 확정하지 않음 |
| 접수 성공 | 새 작업 행을 160ms opacity/translateY 4px 이내로 표시. 화면 전체 재배치 금지 |
| 단계 변경 | 상태 문구 120ms 전환. 고정된 행 높이를 유지하고 스크린리더에 핵심 변화만 알림 |
| 산출물 확정 | 카드 테두리와 배경을 180ms 강조. 파일 하나마다 반복 토스트·소리 없음 |
| 다수 결과 수신 | 알림은 작업 단위로 500ms 묶음 갱신. 실제 결과 수만 누적 |
| 실패 | 해당 단계 옆에 이유·해결 동작 표시. 흔들기 애니메이션이나 입력 초기화 없음 |
| 정지 | 요청 직후 `중지 요청됨`, 안전한 완료 지점에서 `일시정지됨`으로 변경 |
| 로그 추가 | 사용자가 최신 끝부분을 보는 경우에만 따라감. 다른 위치이면 `새 기록 N개` 버튼 표시 |
| 에셋 갱신 | 선택한 파일·포커스·스크롤을 보존. 늦은 응답이 닫은 상세 창을 다시 열지 않음 |
| 모션 감소 설정 | 모든 장식 이동·강조 전환을 생략하고 텍스트 상태만 즉시 갱신 |

애니메이션은 opacity/transform 중심이며 무한 AI 생각하기 효과·장식 WebGL을 넣지 않는다. 기존 3D 뷰어는 선택했을 때만 로드한다. 숨겨진 탭과 앱 창에서 불필요한 UI 폴링·애니메이션은 멈추되 백엔드 실행은 독립적으로 계속된다.

화면 검증 크기는 정상 창 1380×900과 최소 창 820×620이다. 좁은 화면에서는 결과와 상세를 위아래로 배열하되 가로 스크롤 없이 주요 조작에 접근할 수 있어야 한다.

## 13. 권한·품질·데이터 보존

기본 허용은 승인된 프로젝트 자료 조회와 비파괴 로컬 생성·변환·검증·분류·저장이다. 새로운 공유 허용, 새 저장 루트, OAuth·계정 변경, 공개 게시, 유료 호출, 원본 삭제·덮어쓰기는 그 정책으로 허용되지 않는다. 이번 실행기에는 해당 위험 작업 자체를 넣지 않는다.

MCP의 모든 변경 요청은 동일한 프로젝트 범위·원본 접근·규격 검증을 통과한다. 사람이 직접 도구를 호출하는 경로와 AI 작업 경로의 검증 강도가 같아야 한다. 프롬프트 속 `전체 디스크를 읽어라`, `검사를 생략하라` 같은 문장은 실행 정책을 바꾸지 못한다.

자동 검수는 디코딩, 픽셀 크기, 포맷, 알파 채널, 색공간 처리 기록, 용량, 파일 해시, 결과 존재 여부를 뜻한다. 생성 내용의 사실성·브랜드 적합성·법적 권리·스토어 심사 통과를 자동으로 보증하지 않는다. AI 검토 기록도 `보고된 판단`과 실제 도구 검증 증거를 분리한다.

생성 슬롯의 거절·한도·기능 미지원은 안전한 사유 코드로 기록하며 숨겨진 유료 공급자나 다른 계정으로 전환하지 않는다. 인증 토큰·서명 다운로드 주소·API 키·사용자 대화 원문 전체를 이벤트 로그에 저장하지 않는다. 작업 brief와 사용자가 승인한 원본 관계만 필요한 범위에서 보존한다.

## 14. 검증과 완료 게이트

| 검증 시나리오 | 통과 조건 |
| --- | --- |
| 설정 재사용 | 브랜드·폴더·기본 언어를 저장한 뒤 새 작업마다 같은 질문이 반복되지 않음 |
| 원본 재사용 | 승인된 기존 로고를 사용하는 출력 묶음에서 이미지 생성 호출 0회 |
| 여러 규격 | 하나의 master에서 favicon 등 여러 산출물이 생성되고 각각 기존 규격 검사 통과 |
| 누락 캡처 | 앱 스크린샷을 꾸며내지 않고 그 분기만 자료 대기로 남김 |
| 중복 요청 | requestKey/digest 같은 호출은 같은 run, 같은 단계 결과 수신은 같은 artifact 반환 |
| 중간 종료 | 파일 확정 전후와 색인 저장 전후에 프로세스를 종료해도 원본 손실·중복 출력 없이 복구 |
| 동시 접근 | GUI와 MCP가 동시에 수정해도 단계 중복 claim·수정 유실·혼합된 revision 없음 |
| 중지·재개 | 안전 지점에서 정지하고 완료 단계는 보존. 취소 작업에 늦은 파일이 연결되지 않음 |
| 연결 중단 | AI 추가 단계는 대기, 준비된 로컬 단계는 앱이 실행 중인 동안 완료 |
| 자료 권한 | 승인 루트 밖 경로·symlink 탈출·다른 프로젝트 비공유 에셋 요청 차단 |
| 마이그레이션 | v1 백업과 원본 파일 해시 보존, v2 읽기 성공, 구형 바이너리 쓰기 차단 |
| UI 진실성 | 실제 state·artifact·timestamp만 표시. 실패 후 입력·스크롤·선택 보존 |
| 마이크로 인터랙션 | 두 창 크기, 키보드 조작, reduced-motion, 늦은 응답을 실제 화면에서 검증 |
| 실제 ChatGPT | 승인된 연결에서 목표 1회 → 원본 조회/이미지 생성 → 파일 수신 → 결과 묶음까지 실행 |

기존 TypeScript 전체 테스트, Rust 전체 테스트, 에셋 UI 검증, MCP stdio 검증, 타입 검사, macOS 앱 빌드를 회귀 게이트로 사용한다. 새 테스트는 먼저 실패를 확인한 뒤 구현한다. 검증용 원본·프로젝트·결과는 사용자 보관함과 분리된 임시 디렉터리를 사용한다.

테스트 어댑터 검증, 네이티브 WKWebView/파일 선택창 검증, 실제 ChatGPT 연결 검증은 별도로 보고한다. 연결 권한이나 이미지 생성 기능이 없어 마지막 시나리오가 막히면 정확한 차단 지점을 기록하고 로컬 기능 완료와 구분한다.

## 15. 후속 단계와 명시적 기본값

이 문서의 범위는 에셋 작업 흐름으로 제한한다. 구현 계획은 프로젝트/권한 스냅샷, 작업 저장·복구, 로컬 실행, 호스트 MCP, 관찰 UI를 동일한 인터페이스에 맞추어 나눠야 한다. 기존 영상·TTS·SNS는 이 결과가 실제 작동한 뒤 별도의 설계·계획으로 연결한다.

현재 승인된 것은 AI 중심 운영 방향이다. 이 문서와 여기에서 구체화한 기본값을 검토한 다음 구현 계획을 작성한다. 실행 방법은 아직 선택하지 않았으며 Codex 하위 에이전트를 자동 호출하는 결정을 포함하지 않는다. 실제 제품 코드·실행 권한·사용자 데이터의 변경은 이 문서 작성만으로 수행하지 않는다.
