# 영상 템플릿 선택과 미리보기

Toris Studio의 `영상` 화면에서 템플릿을 고르고, 내 주제가 들어간 장면 구성을 확인한 다음 편집을 시작할 수 있습니다. [참고 영상의 템플릿 선택 화면](https://www.youtube.com/watch?v=KEOCKMhaJnA&t=469s)을 참고해 구성했으며, 문구·스타일·CSS 표지는 이 프로젝트에서 새로 작성했습니다.

## 사용 순서

1. 카테고리 또는 검색으로 템플릿을 고릅니다.
2. 주제, 카테고리, 영상 형식, 언어, 장면 수, 길이를 지정합니다.
3. 큰 미리보기에서 장면을 선택하거나 `구성 재생`으로 흐름을 확인합니다. 제목·본문·모션·내레이션 초안을 함께 보여 줍니다.
4. `이 템플릿으로 시작`을 누르면 편집 가능한 새 초안이 열립니다. 저장하지 않은 편집 내용이 있으면 먼저 교체 여부를 확인합니다.
5. 직접 문구·미디어를 수정하거나, 기존 `ChatGPT에 영상 초안 요청`을 사용합니다. 선택한 템플릿의 구성과 현재 입력을 실제 연결된 ChatGPT 대화에 전달합니다. 요청 전달과 완성된 응답 수신은 별도 상태입니다.
6. 프로젝트를 저장하고 기존 Rust 렌더러로 MP4를 출력합니다.

템플릿 선택만으로 이미지를 만들거나 음성을 합성하지 않습니다. 미리보기는 구성 초안이며, 최종 MP4는 기존 네이티브 렌더러의 배치를 사용합니다. `템플릿 없이 직접 구성`으로 기존 작성 흐름도 사용할 수 있습니다.

빈 주제에는 작성된 예시를 보여 줍니다. 새 주제를 입력하면 해당 주제로 구성 지침을 만들며, 검증되지 않은 사실이나 실제 생성된 미디어로 표시하지 않습니다. 수집 콘텐츠 기반 작성에서는 원본 문구·출처·장면 순서·길이를 유지하면서 선택한 템플릿의 색상과 모션을 적용합니다.


## 즐겨찾기·재사용·내보내기

- 카드의 별 버튼으로 즐겨찾기를 저장합니다. `즐겨찾기`와 `최근 사용` 보기는 앱 재실행 뒤에도 유지되며, 최근 사용은 초안을 실제 적용한 순서입니다.
- 미리보기 옆에서 주제·카테고리·형식·언어·장면 수·길이를 바로 바꿉니다. 적용 버튼은 새 미리보기 준비 후 활성화됩니다.
- 편집기의 `복제`는 현재 편집 내용을 독립적인 새 초안으로 복사합니다. 원본 프로젝트와 로컬 미디어는 보존합니다.
- `Markdown 내보내기`는 장면별 시간·제목·본문·내레이션·모션을 문서로 만듭니다. `JSON 내보내기`는 편집 중인 프로젝트를 다시 가져올 수 있는 JSON으로 만듭니다. 저장 경로는 Tauri의 OS 저장 창에서 직접 선택하며, 취소 시 파일을 만들지 않습니다.
- 즐겨찾기 파일은 OS 앱 데이터 폴더의 `video-template-library/state.json`에 저장합니다. 사용자 계정 설정·DB·키체인과 분리하며 알려진 템플릿 ID만 최대 10개씩 저장합니다.

## 구현과 수명 관리

- Rust의 `video_templates` 모듈이 목록과 미리보기, ChatGPT 요청 문구를 만듭니다. 두 IPC 명령 `video_template_catalog`, `video_template_preview`는 로컬 메인 창에서만 호출할 수 있으며 설정·비밀값·네트워크에 접근하지 않습니다. 전체 애플리케이션 명령 등록은 현재 98개입니다.
- 템플릿 ID, 형식, 카테고리, 언어, 길이, 장면 수를 검증합니다. 미리보기 입력에 파일 경로·URL·실행 코드·모델 제공자 필드를 추가하면 거절합니다.
- 기존 렌더 형식을 유지하고 `templateRecipe` 메타데이터만 추가합니다. 같은 템플릿을 다시 사용해도 새 프로젝트 ID를 부여하여 기존 저장 프로젝트를 덮어쓰지 않습니다.
- 입력 변경에 따라 미리보기를 갱신하며, 늦게 도착한 이전 응답은 적용하지 않습니다. 요청 중에는 해당 초안 적용을 막습니다.
- 명시적인 재생 중에만 한 개의 RAF를 사용하고 React 화면 갱신은 초당 최대 10회로 제한합니다. 창 숨김·화면 이동·프로젝트 변경·언마운트 시 재생과 이벤트 리스너를 정리합니다. OS 모션 감소 설정도 반영합니다.

UI의 저장·복원과 ChatGPT 연결은 격리된 메모리 저장소 및 IPC 응답으로 검증했습니다. 별도의 Rust 저장 테스트는 실제 임시 파일을 사용했습니다. 사용자의 계정, 실제 ChatGPT 응답, 설치된 macOS 앱 화면, Windows WebView2, 장시간 OS 메모리 프로파일링은 이번 검증 범위에 포함하지 않습니다. 0.1.22의 빌드·배포는 기존 GitHub Actions의 세 플랫폼 빌드 및 업데이트 서명 검증을 사용합니다. 실제 공개 여부는 해당 Release와 Actions 결과에서 확인합니다.

UI 검증 재실행:

```sh
node scripts/verify-video-templates.mjs
```

Node 24, 설치된 Playwright Chromium, 로컬 Cargo 의존성이 필요합니다. 스크립트는 순수 Rust 예시 프로그램에서 데이터를 만들고 임시 Vite 서버를 실행합니다. 앱의 사용자 설정·DB·키체인·계정·실제 대화는 사용하지 않습니다. Cargo 결과를 재사용하려면 `--fixtures /absolute/path/to/fixtures.json`을 전달할 수 있습니다.

실제 MP4 검증 재실행:

```sh
cargo test --locked --offline --manifest-path desktop/src-tauri/Cargo.toml --no-default-features media::tests::native_template_samples_render_in_both_orientations -- --ignored --exact --test-threads=1
```

FFmpeg·FFprobe와 기존 렌더러가 사용할 수 있는 폰트가 필요하며 출력은 임시 디렉터리에서 검사한 뒤 삭제합니다.
